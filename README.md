# fhOS

Минималистичная операционная система для архитектуры x86, написанная на
**NASM** (ассемблер). Загружается с **ISO-образа** в виртуальной машине,
работает в 16-битном реальном режиме и имеет **графическую оболочку**
(режим VGA 13h, 320×200) с панелью задач сверху, двумя темами и
встроенной файловой системой в оперативной памяти.

```
  +------------------------------------------+
  | fhOS   ДИСК  тема: dark          HH:MM:SS |   <- панель задач сверху
  +------------------------------------------+
  |  fhOS 1.1 - graphical shell               |
  |  Filesystem ready. Type "help" ...        |
  |                                           |
  |  fhos> ls                                 |
  |  readme.txt    91 bytes                   |
  |  hello.txt     24 bytes                   |
  |  notes.txt     34 bytes                   |
  |                                           |
  +------------------------------------------+
```

Готовый **ISO-образ** лежит в разделе
[Releases](https://github.com/gplyno/fhOS/releases).

---

## Что нужно

| Инструмент | Назначение | Примечание |
|-----------|------------|------------|
| **NASM 3.x** | ассемблер | `C:\Users\Девайс\AppData\Local\bin\NASM\nasm.exe` |
| **Python 3.8+** | сборка ISO | |
| **VirtualBox** | запуск | необязательно |

Сборщик сам находит NASM: сначала в переменной окружения `NASM`, затем в
`PATH`, затем по типовым путям.

---

## Сборка

В корне проекта:

```bat
build.bat
```

или

```bat
python build.py
```

Результат:

```
build/fhos.iso      ← загрузочный ISO (~62 КБ)
build/boot.bin      ← stage 1 (512 байт)
build/kernel.bin    ← ядро (~12 КБ)
```

---

## Запуск в VirtualBox

Самый простой способ — скрипт (создаёт ВМ, подключает ISO и включает её):

```bat
run_vm.bat
```

Полезные варианты:

```bat
python run_vm.py --headless   :: без окна
python run_vm.py --remove     :: удалить ВМ
```

> **Важно:** ВМ должна использовать прошивку **BIOS** (Legacy), а не EFI.
> Скрипт создаёт её именно так. Если создаёте ВМ вручную — в разделе
> «Система → Материнская плата» снимите галочку «Включить EFI».

### Вручную

1. Создайте ВМ типа «Other / Unknown», память 32 МБ.
2. Система → носитель загрузки: только **оптический диск**.
3. Подключите `build/fhos.iso` к IDE-контроллеру как DVD.
4. Запустите ВМ.

---

## Запуск в других виртуальных машинах

* **QEMU**
  ```
  qemu-system-i386 -cdrom build/fhos.iso -boot d
  ```
* **VMware** — создайте ВМ, отключите EFI (используйте BIOS) и подключите
  `build/fhos.iso` как CD/DVD.
* **Реальное железо** — запишите ISO на CD/DVD или на USB (через Rufus в
  режиме «BIOS/UEFI: только BIOS»).

| Команда | Описание |
|---------|----------|
| `help` | список команд |
| `clear` | очистить экран |

| `ver` | версия |
| `echo <текст>` | вывести текст |

| `mem` | объём основной памяти |

| `ls` | список файлов |
| `cat <файл>` | показать содержимое файла |
| `write <файл> <текст>` | создать файл и записать текст |

| `beep` | звуковой сигнал |
| `reboot` | перезагрузка |

## Как это устроено

```
boot.asm   →  stage 1: настраивает сегменты, выводит сообщение,
              передаёт управление ядру (1000:0200)
kernel.asm →  ядро: графический режим VGA 13h, клавиатура PS/2,
              панель задач, темы, файловая система, командная оболочка
build.py   →  NASM → образ → ISO (ISO9660 + El Torito, режим no emulation)
```

**Загрузка.** ISO использует загрузочный каталог **El Torito** в режиме
*no emulation*: BIOS сам копирует весь загрузочный образ (stage 1 + ядро)
в память по адресу `1000:0000` и передаёт туда управление. Поэтому код ОС
не читает CD — это максимально совместимо с разными BIOS/виртуальными
машинами.

**Видео (GUI).** Ядро переключает видеокарту в режим **VGA 13h**
(320×200, 256 цветов, линейный буфер `A000:0000`), рисует обои сплошным
цветом, **панель задач сверху** и окно-«терминал». Текст выводится
собственным растровым шрифтом, взятым из **шрифта BIOS** (`INT 10h
AX=1130h`). Палитра загружается в ЦАП видеокарты (порты `0x3C8/0x3C9`);
**тема** — это просто подмена палитры, поэтому переключение мгновенное.

**Файловая система.** Плоская ФС в оперативной памяти: до 24 файлов,
имя до 15 символов, содержимое до 199 символов. При старте создаются
`readme.txt`, `hello.txt`, `notes.txt`. Данные **не сохраняются** между
перезагрузками (дисковый драйвер не реализован).

**Клавиатура.** Ядро отключает PS/2-мышь и маскирует IRQ1/IRQ12, после чего
само опрашивает порты `0x60/0x64`. Маскировка нужна потому, что иначе
обработчик прерываний BIOS забирает скан-коды раньше нас.

**Выключение (`halt`).** Питание выключается через ACPI (S5). Сначала ядро
пытается найти таблицу FADT и порт `PM1a_CNT`; если таблицы лежат выше 1 МБ
(недостижимы из real mode, как в VirtualBox), используются стандартные
порты `PM1a_CNT` эмуляторов (VirtualBox `0x4004`, QEMU `0x0604`,
Bochs `0xB004`). Если выключить не удалось — процессор останавливается
(`cli; hlt`).

**Отладка.** Весь вывод (в том числе графический) дублируется на **COM1**
(через `INT 14h`). Это удобно для отладки: например, в VirtualBox можно
привязать COM1 к файлу
(`VBoxManage modifyvm <vm> --uart1 0x3F8 4 --uartmode1 file serial.log`) и
читать вывод ОС из файла.

## Ограничения

* Только **BIOS/Legacy** загрузка (UEFI не поддерживается).
* Это «живая» система — она работает прямо с ISO и **не устанавливается на
  диск**. Файловая система живёт в оперативной памяти и **не сохраняется**
  между перезагрузками.
* Однозадачный реальный режим, без защиты памяти и многозадачности.
* Мышь не поддерживается: тема переключается командой `theme`.
